Project Abstract

Port littlefs v2 into RTEMS as a native filesystem. After completing v2 integration, the project will explore and provide initial integration for littlefs v3.

Project Scope

Medium Project (175 hours)

Project Description

RTEMS supports flash-based filesystems such as JFFS2; however, there is a need for a lightweight, modern alternative optimized for constrained embedded systems such as microcontrollers. littlefs addresses this by offering low footprint, low RAM usage, fast mount times, and a simple design specifically designed for microcontroller environments.

This project will integrate littlefs into RTEMS under the /contrib directory and implement a wrapper layer that maps RTEMS VFS operations to littlefs APIs. The design will follow an approach similar to the existing JFFS2 integration, providing RTEMS with a compact and robust alternative for flash storage.

After completing the littlefs v2 integration, the project will explore and provide initial integration for littlefs v3, which introduces changes in API, configuration, on-disk format, and a redesigned file storage structure, and is currently in an experimental stage.

In addition, documentation will be created, including API-level documentation similar to the RTEMS JFFS2 documentation (Doxygen-based), along with a usage guide for developers.

The project will be maintained using modular design, documentation, and alignment with RTEMS coding practices enabling easy future contributions.

Deliverables to task mapping:

Flash interface integration:
3. Flash abstraction layer: Implement a flash abstraction like rtems_lfs_flash_control providing callbacks for read, prog, erase, and sync as required by lfs_config.

Filesystem mount and unmount capability:
5. Mount flow: Implement rtems_littlefs_initialize() to configure lfs_config, call lfs_mount(), or fall back to lfs_format() + lfs_mount() if mount fails.
6. Unmount flow: Implement rtems_littlefs_fsunmount() to unmount using lfs_unmount().

RTEMS VFS integration:
1. VFS integration: Implement rtems_littlefs_ops to map RTEMS filesystem hooks to LittleFS-based implementation, making LittleFS appear as a native RTEMS filesystem.
2. File handler dispatch: Implement rtems_littlefs_set_location() to select appropriate handler tables for regular files and directories (and symlinks if supported).

File and directory operations support:
7. Inode management: Implement a littlefs_inode_info structure to map RTEMS inodes to LittleFS objects, storing path/type and embedding lfs_file_t or lfs_dir_t for open handles, handle creation via lfs_file_open()/lfs_mkdir() and deletion via lfs_remove().
8. Directory management: Implement rtems_littlefs_dir_read() using lfs_dir_open(), lfs_dir_read(), and lfs_dir_close().

Path resolution and navigation:
9. Path evaluation: Implement rtems_littlefs_eval_path() using path-string-based traversal since LittleFS is path-oriented.

Metadata and attribute handling:
10. Mode mapping: Implement translation between RTEMS/POSIX mode bits and LittleFS modes.
4. Superblock and filesystem state: Implement rtems_littlefs_fs_info to hold LittleFS state, including lfs_t and lfs_config.

Error handling and POSIX compliance:
11. Error translation: Implement mapping between LittleFS error codes and RTEMS/POSIX errno.

File I/O operations (read/write/seek):
12. File read path: Implement rtems_littlefs_file_read() using lfs_file_read() with proper offset handling via lfs_file_seek().
13. File write path: Implement rtems_littlefs_file_write() using lfs_file_write() with correct offset/append handling.

Advanced file operations (truncate, rename):
14. Truncate support: Implement rtems_littlefs_file_ftruncate() using lfs_file_truncate().
15. Rename functionality: Implement rename support using lfs_rename().

Filesystem statistics and monitoring:
16. Filesystem statistics: Implement rtems_littlefs_statvfs() using lfs_fs_size() and configuration parameters (block size and count) to derive total and free space.
17. Flash usage reporting: Implement rtems_littlefs_get_info() to report runtime details such as total flash size, block size, used blocks, and free blocks, etc.
